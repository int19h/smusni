## Mechanism and public paths

Spec §7.1 permits an Act wherever Discourse is required, by notation rather
than subtyping. PerformSource's D is such a position. The old implementation
and its literal-Assert negative were wrong: a typed Act value must be performed.

The normalizer infers the operand's type from the declared environment. An
Act-valued expression A becomes `(Do (Perform Host A))`; a returning performance
is discarded through Do; an actual Discourse stays a Discourse. Act operands
already under Do become Perform Host operands, so A, `(Do A)` and
`(Do (Perform Host A))` have the same normalized tree. This is not a test of
the source head being Assert. Variables, lambda applications and Let-produced
Act values follow the same path. A appears once; no binder or Context/Vague
site is generated, and the existing S/C1/D scopes are retained. C1 remains
already resolved and is not traversed by this notation pass.

| API | Contract |
|---|---|
| Racket `infer-core` | Normalizes the F01 continuation before checking the actual Discourse AST. |
| Racket `normalize-source-core` | Returns the typed source-normalized AST using the supplied environment. |
| Racket `elaborate-core ... #:environment env` | Performs existing source elaboration and typed notation normalization; without an environment, open-term normalization is deferred to `infer-core`. |
| Lean `decodeSourceCore` | Decodes primitive source notation with declared free-variable types, then returns its normalized AST and original site metadata. |
| Lean `synthesizeSource` | Returns both the normalized AST and its deep typing result. |
| Lean production `elaborateSurface` / `elaborateCore` | Normalize the F01 expected-Discourse continuation with its read/o environment. |
| Lean M1 `decodeClosedCore` and deep `synth` | Remain structural decoding and strict core typing; raw shorthand is not silently a Discourse subtype. |

`M2SourceNotation.lean` provides the implementation and
`synthesizeSource_sound`: the typing theorem applies to the returned canonical
AST, never the unnormalized input. Wrapper site-use/site-occurrence invariance
and renaming/substitution laws are proved. Source-normalized cases are reported
as type-directed expansion with `expected-Discourse source notation`, not as
unchanged input; no fictitious §12 definition or primitive is added.

Typed nonliteral controls exposed an existing representation mismatch: force
annotations decoded as type variables while constructors returned force indices.
Act/ActOccurrence annotations now decode their force tag as an index (including
Question in force position, separately from the Question sort). No compatibility
or semantic subtype is added. This made six retained performance-Bind paths
reach previously excluded typing rules. All three existing performance-Bind
rules now have declarative premises and complete/sound bridges. A typed
`PerformanceBody` certificate validates exactly Act, PerfComp or Discourse
bodies; Content and RefComp bodies reject. The computation premise is a genuine
synthesized PerfComp typing, not an assumed desired checker output.
